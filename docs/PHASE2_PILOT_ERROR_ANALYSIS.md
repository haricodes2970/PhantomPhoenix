## 1. Executive summary

The saved official aggregate report contains 50 processed samples: 25 real and 25 fake, with zero exclusions and zero inference errors. At a 0.50 threshold, the model detects only 6 of the 25 fake samples. It produces no false positives on the 25 real samples in this pilot.

| Recall (fake class) | 0.2400 |

| Confusion matrix `[[TN, FP], [FN, TP]]` | `[[25, 0], [19, 6]]` |
| Processed / excluded / inference errors | `50 / 0 / 0` |

**Main conclusion:** this model/processing setup has poor fake-class recall at the current 0.50 decision threshold on this pilot. The zero-FP result is useful but does not compensate for missing 19 of 25 fake samples. Do not present this result as proof of broad real-world performance.

The per-sample JSON explicitly says it came from a **second inference pass** and that the official aggregate metrics remain in `evaluation_report.json`. Recomputing the metrics from the uploaded per-sample records gives the same accuracy, precision, recall, F1, ROC-AUC, and confusion matrix. Keep both files and retain this provenance note.

## 5. Interpreting ROC-AUC and recall

ROC-AUC (`0.896`) is a ranking metric: it measures how often a randomly selected positive example receives a higher score than a randomly selected negative example, averaged over thresholds. Recall (`0.24`) is the fraction of fake samples detected at the particular threshold `0.50`.

These can coexist: the score ordering can look relatively strong overall while most fake scores remain below the chosen decision threshold. In this sample, many fake scores are clustered close to zero, so the 0.50 operating point misses them. The AUC does **not** by itself establish that the probabilities are calibrated, nor does it prove that moving the threshold is the correct fix.

Potential explanations to investigate—not conclusions from this dataset—include:

1. **Calibration / score-distribution drift:** the model's scores may not map to useful decision probabilities for this dataset or preprocessing path.
2. **Generator or domain coverage:** the model may respond differently to some image-generation families or image styles.
3. **Sampling noise / dataset composition:** 50 examples, including small per-family groups, may not represent the deployment distribution.
4. **Preprocessing and source effects:** resizing, center cropping, image compression, or dataset collection can influence model inputs and scores.

The current evidence cannot separate these explanations. Avoid asserting one cause without a controlled follow-up experiment.

## 6. Limitations and research integrity

- `n=50` is a pilot sample, not a sufficient basis for claims of generalization or deployment accuracy.
- The sample has a balanced 25/25 class distribution; production prevalence may differ, which can change precision and other operational metrics.
- Generator family labels are dataset metadata, not independent proof of provenance.
- A high fake probability is a model inference, not verified proof that an image is synthetic or manipulated.
- No model weights, production thresholds, or production modules were changed by this analysis.
- Dataset licence recorded for the OpenFake pilot is **CC BY-NC 4.0**. Preserve attribution and respect the non-commercial restriction when sharing or reusing the dataset.

## 7. Reproduction

Place the script at `scripts/analyze_pilot_predictions.py` and this document at `docs/PHASE2_PILOT_ERROR_ANALYSIS.md`.

From the repository root, run:

```bash
python scripts/analyze_pilot_predictions.py \
  datasets/openfake_pilot/results/per_sample_predictions.json \
  --report datasets/openfake_pilot/results/evaluation_report.json
```

The script uses only the Python standard library. It recomputes metrics from the saved predictions, cross-checks the official aggregate report when supplied, prints a threshold sweep, lists false-negative families, and flags generator groups with `n <= 2`. It does not run model inference and does not change production configuration.

If the cross-check warns that the files do not match, investigate the documented difference between inference passes before combining the results. The official aggregate report remains the source of record for the reported aggregate evaluation.

## 8. Recommended next experiment

1. Freeze this pilot and its outputs as a reproducible baseline.
2. Build a larger, stratified validation set with more examples per generator family and a clearly documented real-image source.
3. Separate threshold selection from final evaluation: tune on a validation split, then report final metrics on a held-out test split.
4. Report precision-recall curves, ROC-AUC, confusion matrices, per-family sample counts, confidence intervals where practical, and calibration diagnostics.
5. Test preprocessing and compression effects as controlled ablations.
6. Only then consider changing thresholds, recalibrating scores, or replacing/fine-tuning the detector.

**Decision:** keep the current production policy unchanged; treat low fake recall as a known limitation and prioritize a larger controlled evaluation before changing the model or operating threshold.
